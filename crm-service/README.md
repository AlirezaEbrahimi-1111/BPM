# crm-service (Go)

سرویسِ CRM. یک برنامهٔ Goِ جدا که کنارِ اپِ PHPِ اصلی روی همان سرور اجرا می‌شود،
همان دیتابیس را می‌خواند و همان توکنِ JWTِ لاگین را می‌شناسد.

**اپِ PHP کاملاً مستقل است — اگر این سرویس خاموش شود، فقط مسیرهای `/crm/` از کار می‌افتند.**

---

## وضعیت: فقط «بستر» آماده است — اینجا متوقف شده

آنچه ساخته شده:

| بخش | فایل | حالت |
|---|---|---|
| اسکلتِ سرویسِ Go (health + احراز هویتِ JWT) | `main.go` | کامپایل می‌شود، لوکال تست‌شده |
| اسکیمای دیتابیسِ کاملِ CRM | `../migrations/20260902_140000_create_crm_foundation.php` | نوشته‌شده، **هنوز روی سرور اجرا نشده** — دفعه‌ی بعدِ دیپلویِ PHP خودکار اجرا می‌شود |
| نقشِ «مدیر فروش» | همان مهاجرت: ستونِ `users.is_sales_manager` | نوشته‌شده |
| استقرار روی VPS (systemd + Apache proxy + یوزرِ DBِ محدود) | `deploy/` | مستند، **هنوز اجرا نشده** |

**هیچ صفحه/APIِ قابلیت‌محوری هنوز نوشته نشده** — عمداً. قدمِ بعدی (هر وقت برگشتی):
اجرای `deploy/DEPLOY.md` روی سرور، بعد اولین قابلیت (لیستِ مشتری + افزودن + تأییدِ مدیرِ فروش).

### ماژولِ دومِ همین سرویس: «فاکتور رسمی» (فقط سازمانِ ۱)

بسترِ دیتابیسش هم آماده است:
`../migrations/20260902_150000_create_official_invoice_foundation.php` —
جدول‌های `inv_*` (کالا، دو انبار، دفترِ حرکتِ انبار، تأمین‌کننده، فاکتورِ خرید،
سربرگِ فروشنده، تنظیمات، فاکتورِ رسمی + اقلام، درخواستِ مهمان) + ستونِ
`users.is_create_official_invoice`. مشتری از `crm_customers` به‌اشتراک است.
هیچ کدِ Go/صفحه‌ای برایش نوشته نشده. جزئیاتِ اسکوپ در حافظه.

معماریِ انتخاب‌شده: مرورگر → Apache مسیرِ `/crm/api/*` را مستقیم به سرویسِ Go می‌دهد؛
خودِ Go همان توکنِ JWT را چک می‌کند (مثلِ `includes/auth.php`).

## فاز فعلی (۰): فقط سلامت + احراز هویت

| مسیر | احراز هویت | کار |
|---|---|---|
| `GET /crm/api/health` | ندارد | سلامتِ سرویس و اتصالِ دیتابیس |
| `GET /crm/api/me` | توکنِ `Bearer` (همان `auth_token` مرورگر) | id / سازمان / نامِ کاربرِ جاری |

## راه‌اندازیِ محلی (روی ویندوزِ خودت)

### ۱) نصبِ Go
از <https://go.dev/dl/> نسخهٔ ویندوز (`.msi`) را نصب کن. بعد در ترمینالِ جدید:

```bash
go version        # باید 1.22 یا بالاتر باشد
```

### ۲) گرفتنِ وابستگی‌ها

```bash
cd crm-service
go mod tidy        # go.sum را می‌سازد و دو کتابخانه را دانلود می‌کند
```

### ۳) ساختِ فایلِ پیکربندی

```bash
cp config.example.json config.json
```

`config.json` را باز کن و پر کن:
- `db_name` = همان نامِ دیتابیسی که در `../config/config.php` هست.
- `db_user` / `db_pass` = **فعلاً برای تستِ محلی** می‌توانی همان یوزرِ دیتابیسِ اصلی را بگذاری.
  (روی سرور یک یوزرِ محدودِ جدا می‌سازیم — به بخشِ «استقرار» نگاه کن.)
- `jwt_secret` = **دقیقاً** همان مقدارِ `jwt_secret` در `../config/config.php`.
  اگر فرق داشته باشد، `/crm/api/me` همیشه ۴۰۱ می‌دهد.

> `config.json` در `.gitignore` است و هیچ‌وقت کامیت نمی‌شود.

### ۴) اجرا

```bash
go run .
```

باید ببینی: `crm-service روی http://127.0.0.1:8090 ...`

### ۵) تست

سلامت (نیازی به توکن ندارد):
```bash
curl http://127.0.0.1:8090/crm/api/health
# → {"ok":true,"service":"crm-service","db":true,...}
```

با توکن: در مرورگر واردِ سایتِ اصلی شو، `F12` → `Console` → بزن:
```js
localStorage.getItem('auth_token')
```
مقدار را کپی کن و:
```bash
curl -H "Authorization: Bearer <همان مقدار>" http://127.0.0.1:8090/crm/api/me
# → {"user_id":19,"organization_id":1,"name":"...","activity_section":"..."}
```

## دیباگِ مبتدی

- **خطای کامپایل** = Go قبل از اجرا خطا را نشان می‌دهد و اجرا نمی‌کند. متن خطا مسیرِ فایل و شماره خط دارد.
- **لاگ‌ها** روی ترمینال چاپ می‌شوند (هر request یک خط). برای پیامِ خودت: `log.Printf("مقدار x = %v", x)`.
- **`db: اتصال ناموفق`** = `config.json` اشتباه است (host/port/user/pass/name).
- **`/crm/api/me` همیشه ۴۰۱** = `jwt_secret` با `config/config.php` یکی نیست، یا توکن منقضی شده (دوباره لاگین کن).
- **تغییرِ کد** → `Ctrl+C` → دوباره `go run .`. (هر بار از نو کامپایل و اجرا می‌شود، سریع است.)
